# Booth demo runbook — rep board + real WhatsApp follow-up

The `/demo` flow now lands on a **simulated rep board** after extraction: four
buckets (deals at risk, buying intent, needs follow-up, revive) generated by
Bedrock from the prospect's own crawled catalog, with AI quotes, delivery
times, and follow-up scheduling. A QR panel lets the prospect message the demo
WhatsApp number; the webhook binds their wa_id to the session, they appear on
the board as a live lead, and the follow-up they schedule ("in 1 minute") is a
**real Cloud API send to their own phone** — legal because their inbound
message opened the 24h customer-service window.

Everything degrades gracefully: without the WhatsApp secret configured, the QR
panel simply never renders and the board demo still works end to end.

## 1. Deploy (do first)

```bash
cd demo-backend
npx cdk deploy DemoApiStack --profile anytrail --require-approval never
cd .. && vercel deploy          # preview first; `vercel --prod` after rehearsal
```

The CDK deploy creates an empty secret `anytrail/demo/whatsapp` and grants the
Lambdas read access. Routes added: `POST /demo/wa/link`, `GET /demo/wa/status`,
`POST /demo/wa/send`, `GET|POST /demo/wa/webhook`, plus the `board` action on
the streaming Lambda.

## 2. WhatsApp Cloud API setup (Meta side, ~30 min)

1. <https://developers.facebook.com> → your business app (or create one) →
   add the **WhatsApp** product.
2. **Add a phone number** you own to the WABA (API onboarding, NOT
   coexistence — the number must not be registered on the WhatsApp app; if it
   is, delete the account in the app first). Verify by SMS/voice OTP.
3. Note the number's **Phone number ID** (WhatsApp → API Setup).
4. **Permanent token**: Business Settings → Users → System users → create
   (admin) → generate token with `whatsapp_business_messaging` +
   `whatsapp_business_management` scopes. (The API Setup page's temporary
   token dies in 24h — mid-conference. Use the system-user token.)
5. **Webhook**: WhatsApp → Configuration →
   - Callback URL: `https://3cyy3hfm3a.execute-api.us-east-1.amazonaws.com/demo/wa/webhook`
   - Verify token: any string you invent — same value goes in the secret below.
   - Save (this fires the GET verification — the secret must be set FIRST),
     then subscribe to the **messages** field.
6. App secret (Settings → Basic → App secret) enables webhook signature
   verification. Recommended; leave `""` to skip.

## 3. Set the secret

```bash
aws secretsmanager put-secret-value --profile anytrail \
  --secret-id anytrail/demo/whatsapp \
  --secret-string '{
    "token": "<system-user token>",
    "phoneNumberId": "<phone number id>",
    "waNumber": "5215XXXXXXXXX",
    "verifyToken": "<the string you invented>",
    "appSecret": "<app secret or empty string>"
  }'
```

`waNumber` is the demo number in wa.me digits form (country code, no `+`).
The Lambda caches secrets per warm container — after changing the secret,
either wait ~15 min or redeploy to force fresh containers.

## 5. Night before

- Pre-run the demo on 2–3 domains of prospects you expect at the booth (and on
  a safe default like a known customer's site). Profile AND board are cached
  per domain for 7 days — a pre-run makes the booth run near-instant and
  immune to Firecrawl flakiness.
- Charge a phone hotspot. If venue wifi dies, everything (Vercel + AWS) works
  over the hotspot; nothing runs locally.

## 6. Booth-day notes & failure modes

- **The send only works to the phone that scanned the QR** (their message
  opened the 24h window). If someone types a number instead of scanning,
  there is no window and no card — the QR is the only path, by design.
- "Send failed" toast usually means: they edited the code out of the prefilled
  message (webhook never bound their session), or a token problem. Fallback:
  scan the QR with your own phone — your card appears and the buzz moment
  still lands, on your phone held next to theirs.
- The "1 minute" follow-up timer lives in the browser tab. Don't close the tab
  before it fires. "In 1 hour" / "Tomorrow 9:00" only show scheduled state.
- Rate limits (all per IP per day, and the venue is one IP): 200 demo starts,
  100 WhatsApp sends, 20k status polls. Fine for a booth day.
- A brand-new Cloud API number can message limited numbers of NEW recipients
  per day (tier starts at 250 business-initiated); session replies (our case)
  are not tier-limited. Sending a couple of messages from the number to
  friends today doesn't hurt its quality rating.
- Kill switch for crawl/leads spend: Lambda env `DEMO_OUTBOUND=disabled`.

## 7. The 5-minute script

1. Ask for their website. Type it. While it crawls: "scan this — you're about
   to become your own hottest lead" (masks the wait).
2. Board reveal: "this is your reps' Monday morning, built from your actual
   catalog — these are your products, your prices."
3. At-risk card → open → show the stalled thread and the suggested reply.
4. Intent card → Generate quote → "your rep taps once, the quote is built from
   your list prices." Delivery time on the same or next card.
5. Their own card (top of Needs follow-up, green, "YOU") → schedule follow-up
   → In 1 minute → keep talking pricing… their phone buzzes. Close:
   "that's what your customers feel. Want it on your real number?" → /schedule.
